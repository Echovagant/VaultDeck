# ADR-004 对象存储布局

| 项       | 内容                                                                                                                                     |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 状态     | Accepted（2026-11-16）                                                                                                                   |
| 决策者   | 开发方（单人开发）                                                                                                                       |
| 关联     | `docs/design/design.md` §3.1、§3.3、§6.1、§9.2、R2                                                                                       |
| 需求依据 | REQ-F-34（多项目引用不复制）、REQ-F-35～39（分片独立校验/幂等/合并比对）、REQ-F-08（秒传）、REQ-N-16（SHA-256）、REQ-N-19（10 天回收站） |

## 背景

存储在单机 3 盘 RAID5（业务可用约 11.41 TiB，L2 理论值），文件单档上限 20 GB，需支持：分片上传与断点续传、秒传、同一内容被多项目引用而不复制、删除进回收站 10 天后物理清除、单分片损坏不导致整文件不可读、下载走零拷贝与 Range。

关键约束是"元数据变更"与"物理字节"必须解耦：重命名、移动、多项目引用都不应搬动大文件字节。

## 决策

采用**内容寻址对象存储 + 分片暂存区 + 引用计数**，全部落在本地文件系统。

```
${DATA_ROOT}/
├── staging/{sessionId}/{index}.part                     # 未完成上传
├── objects/{sha256[0:2]}/{sha256[2:4]}/{sha256}.blob    # 不可变内容寻址对象
├── objects/.tmp/                                        # 合并临时
├── cache/preview/{sha256}.pdf                           # 预览缓存（LRU）
├── tmp/                                                 # 打包 spool 回退
├── backups/  /  logs/
```

规则：

1. 对象路径完全由 `sha256` 决定（两级 256×256 桶），内容不可变；任何"变更"都是新对象 + 引用切换。
2. 元数据 `file` 与物理 `object` 之间用 `file_object_ref` 多对多关联，`object.ref_count` 事务内维护，物理删除条件为"引用归零且无回收站引用且无进行中会话"。
3. 分片独立落盘（`staging`），每片独立 SHA-256；合并时逐片读取 + 增量计算整文件 SHA-256，一次读完成"合并 + 校验"。
4. 对象合并完成后 `rename`（同卷原子）并置只读；运行账号对 `objects` 只有追加与只读权限。
5. 秒传 = `objects` 中已存在同 `sha256` 且同 `size`，直接建引用，不传正文。
6. **不做文件内容静态加密**（REQ-C-21 已定；Windows 下 BitLocker 为后续可选方向）：内网 + 物理安全 + 备份加密承担机密性。
7. 删除入回收站只改 `file.status` 与写 `trash_entry`，对象引用不变；到期清理才减引用。

**平台说明（ADR-007）**：Windows 下无 POSIX 权限位，只读以 NTFS 只读属性 + 目录 ACL 表达；`rename` 覆盖语义不同，目标路径由 `sha256` 唯一因此不产生覆盖；迁移手段由"硬链接"改为复制/重写。**本 ADR 的规则 4（权限位）与"硬链接迁移"表述被 ADR-007 取代；规则 6（不做静态加密）已由 REQ-C-21 确认。**

## 备选方案与否决理由

| 方案                              | 否决理由                                                                                       |
| --------------------------------- | ---------------------------------------------------------------------------------------------- |
| 数据库 BLOB 存文件正文            | 20 GB 级对象会摧毁备份与恢复窗口；无法 Range 零拷贝；数据库体积与 WAL 膨胀                     |
| 按项目/文件夹真实目录存文件       | 重命名与移动需搬动字节（违背低返工与性能目标）；多项目引用需复制；秒传难以实现                 |
| 整文件单文件存储（不分片）        | 断点续传粒度粗；单点损坏即整文件不可读（违反 REQ-F-35）；上传中断产生大量半成品                |
| 引入 MinIO 等对象存储服务         | 多一个常驻服务与一份运维面；单机 RAID 上无额外收益；可作为未来 `StoragePort` 的实现候选        |
| 文件级静态加密（如 age/gpg 封装） | 使 Range 与 `sendfile` 失效、破坏零拷贝；千兆链路下 CPU 成为瓶颈；密钥管理与恢复复杂度显著上升 |
| 保留分片而不合并为整文件          | 下载需逐片拼接、无法零拷贝、对象去重困难；合并后的整文件对象更利于 Range 与巡检                |

## 后果

**正面**：重命名/移动/多项目引用均为 O(1) 元数据操作；秒传与内容去重天然成立；单分片损坏可定位重传；下载可 `sendfile`；备份按对象增量，未变内容不重复写。

**负面**：① 引用计数是正确性关键，任何路径漏减即产生"永不回收"的对象（需巡检对账任务）；② 目录层级与只读权限依赖运维纪律（Windows 下为 NTFS 只读属性 + ACL，见 ADR-007）；③ 回收站期间对象仍占容量（已在 design.md §9.2 计入语境 E）；④ 无静态加密意味着"拿到磁盘即拿到内容"，需以物理安全与备份加密弥补（REQ-C-21 已定，后续可选 BitLocker）；⑤ 对象不可变导致"改名"不改字节，但会让备份增量识别为新文件记录，需靠 sha256 去重；⑥ **本期运行在 Windows 单机（可能单盘），无 RAID5 冗余（RAID5 属未来目标机，R12）**，本 ADR 只决定"布局"，不提供冗余。

**必须配套**：月度巡检（REQ-N-17）比对 `file.sha256 ↔ object.sha256 ↔ 实际字节`；引用计数对账（`ref_count` vs `file_object_ref` 行数）；孤儿对象清单与人工确认后清理。

## 替换成本

| 场景                                      | 成本（L3 估算）                                                          |
| ----------------------------------------- | ------------------------------------------------------------------------ |
| 换 `StoragePort` 实现（如改对象存储服务） | ≤1 天改实现 + 装配；**已有数据迁移另需 3–5 天**（按对象批量写入 + 校验） |
| 加静态加密                                | 2–5 天（流式加解密 + Range 对齐 + 密钥轮换），且需重新压测吞吐           |
| 调整目录分片层级                          | ≤0.5 天（仅实现内部），已有数据可用硬链接/重写迁移                       |

## 复评触发条件

1. 实测巡检发现引用计数不一致率 >0.1%。
2. 对象数超过 500 万导致单桶目录性能下降。
3. 需求方明确要求"磁盘离线即不可读"（触发 D2 决策为"需要静态加密"）。
