# ADR-003 文档预览策略

| 项       | 内容                                                                                 |
| -------- | ------------------------------------------------------------------------------------ |
| 状态     | Accepted（2026-11-16）                                                               |
| 决策者   | 开发方（单人开发）                                                                   |
| 关联     | `docs/design/design.md` §2.5、§3.4、§6.1、R1、R9                                     |
| 需求依据 | REQ-F-25～28、REQ-N-11（预览时延）、REQ-N-33（无公网依赖）、OQ-10（不做水印/禁下载） |

## 背景

需在浏览器内直接查看 doc、docx、xls、xlsx、pdf，用户不安装 Office、不装插件；PDF 上限 50 MB、Office 上限 100 MB（OQ-04）。环境完全离线、无公网转换服务；单机 16C/32T、64 GB 内存需同时承担上传、下载、统计与转换。

预览不得绕过下载权限，也不得向未授权用户暴露原始文件地址（REQ-F-28）。预览水印与禁下载已明确推迟到二期（OQ-10）。

## 决策

采用**混合策略 + 严格降级**：

1. PDF：前端 pdf.js（自托管 worker 与 cmaps）通过 Range 分段加载，服务端不转换。
2. Office 全系（doc/docx/xls/xlsx/ppt/pptx）：后端以 **LibreOffice headless** 转 PDF，结果按对象 `sha256` 缓存；前端仍用 pdf.js 渲染。
3. 转换失败：前端 `docx-preview` / `SheetJS` 轻渲染（仅 docx/xlsx）。
4. 仍失败：明确提示原因 + 下载入口（REQ-F-27）。

工程约束：

- 每次转换启动独立 `soffice` 子进程（不复用常驻进程），独立 `UserInstallation` 临时 profile，设置内存与时长上限，超时以进程组 `SIGKILL` 回收。
- 并发上限 2，超出排队；失败结果不缓存，仅计数用于健康视图。
- 预览与下载共用同一权限网关，命中缓存同样校验权限并写审计；缓存路径不暴露给浏览器。
- 安装包附带 CJK 基础字体，避免中文排版偏移。
- **平台说明（ADR-007）**：Windows 下转换器为 `soffice.exe`，超时以 `taskkill /PID <pid> /T /F` 回收进程树（无 POSIX 进程组）；字体来自 Windows 字体库，需验证 PDF 内嵌。**本 ADR 的进程回收方式被 ADR-007 取代。**

## 备选方案与否决理由

| 方案                                     | 否决理由                                                                                         |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------ |
| OnlyOffice / Collabora Online 文档服务器 | 需额外常驻服务、容器与 2 GB 以上内存，授权与部署复杂度高；需求只要"查看"，不需要协同编辑与批注   |
| 纯前端 docx-preview / SheetJS 作主方案   | docx 复杂排版保真不足；老式 `.doc`/`.xls` 不支持；大 xlsx 前端解析会阻塞主线程，与 REQ-N-11 冲突 |
| 云转换服务（含自建在线转换）             | 违反 REQ-N-33 与 REQ-C-03（无公网依赖）                                                          |
| 服务端栅格化为图片                       | 丢失文字选择与缩放清晰度；大文档转换更慢、缓存体积更大                                           |
| 浏览器内置 PDF viewer                    | Chrome/Firefox 行为不一致，无法注入鉴权与审计逻辑                                                |

## 后果

**正面**：完全离线可用；Office 保真度在可选方案中最高；PDF 路径零转换开销；三级降级保证任何文件都有明确出口；转换器可被适配层隔离。

**负面**：① 首次转换有冷启动延迟（L3，需实测），可能不满足 100 MB Office 10 秒目标；② 字体缺失导致排版偏移（R1）；③ 子进程有内存泄漏与僵尸进程风险（R9）；④ 缓存占用磁盘，需 LRU 配额（建议 200 GB）。

**可观测性**：转换成功率、P50/P95 转换时长、活跃 `soffice` 数、缓存命中率、失败原因分类。

## 替换成本

| 场景                                       | 成本（L3 估算）                                                                                 |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| 换转换器（如改 OnlyOffice 或自研渲染服务） | ≤1 天接 `PreviewPort`（`capabilities` / `render` / `invalidate`），业务与前端零改动；部署包另计 |
| 降级为"纯前端渲染"或"仅下载"               | ≤0.5 天，改 `capabilities` 返回值即可                                                           |
| 换成内嵌在线编辑                           | 超出本期范围，需重新评审需求与资源预算                                                          |

## 复评触发条件

1. M2 真实样本试转成功率 <80%，或 100 MB Office 转换 P95 >20 s。
2. 连续 50 次转换后 `soffice` RSS 持续增长且无法回收。
3. 用户明确要求在线编辑、批注或版本对比（超出本期非目标）。
