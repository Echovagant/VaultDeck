# 备份与恢复

## 1 目标

| 指标          | 目标      | 说明                            |
| ------------- | --------- | ------------------------------- |
| RPO           | ≤ 24 小时 | 每日增量备份一次，每周一次全量  |
| RTO（单文件） | ≤ 8 小时  | 从最近快照恢复单个对象          |
| RTO（单项目） | ≤ 8 小时  | 按项目前缀恢复对象 + 数据库记录 |
| RTO（全库）   | ≤ 48 小时 | 受备份介质吞吐限制，L2 估算     |

## 2 备份内容

| 内容       | 方式                      | 说明                               |
| ---------- | ------------------------- | ---------------------------------- |
| 数据库     | `pg_dump --format=custom` | 含账号、项目、文件元数据、审计     |
| 文件对象   | restic 备份存储目录       | 分片合并后的内容寻址对象           |
| 迁移与配置 | restic 备份（随发布包）   | 迁移脚本在发布包内，配置在私有目录 |

预览缓存（`previews/`）**不备份**：可由原文件重新转换。

## 3 仓库与密码

- 仓库：restic 仓库，建议放在**外置介质**，不要与生产数据同盘。
- 加密：restic 默认加密，仓库内看不到明文。
- 密码：单独保存在离线位置。**密码丢失即数据不可恢复**，这不是可选项。
- 版本锁定：restic 0.19.1（Windows amd64），与发布包一起分发。

## 4 备份命令

```powershell
.\scripts\backup\backup.ps1 `
  -AppHome <VAULTDECK_HOME> `
  -DatabaseUrl <连接串> `
  -Repository <restic 仓库路径> `
  -PasswordFile <密码文件> `
  -StoragePath <对象存储目录> `
  -PgBin <pg_dump 路径> `
  -ResticPath <restic 路径>
```

脚本步骤：

1. `pg_dump` 到临时目录，生成自定义格式 dump。
2. `restic backup` 同时纳入 dump 与对象存储。
3. `restic forget --keep-daily 7 --keep-weekly 4 --keep-monthly 6 --prune`。
4. 删除临时 dump，输出耗时与快照标记。

建议用任务计划在每日固定时间执行，只保留一个兜底任务，避免与应用内调度双跑。

## 5 恢复命令

### 5.1 全部恢复

```powershell
.\scripts\backup\restore.ps1 `
  -Repository <仓库路径> `
  -PasswordFile <密码文件> `
  -TargetDir <临时恢复目录> `
  -Snapshot latest
```

恢复后目录结构按备份时的绝对路径展开，对象文件位于 `<目标目录>\...\storage\objects\`。

### 5.2 单文件恢复

```powershell
.\scripts\backup\restore.ps1 -Repository <仓库> -PasswordFile <密码> `
  -TargetDir <临时目录> -Snapshot <快照ID> -Include "<对象相对路径>"
```

单个对象恢复通常在秒级完成，具体上限取决于对象大小。

### 5.3 数据库恢复

```powershell
pg_restore --no-owner -d <目标数据库> <dump 文件>
```

生产恢复步骤：

1. 停止后端服务（避免写入竞争）。
2. 恢复数据库到新库，校验计数后再切换连接串。
3. 恢复对象目录到 `data/storage`。
4. 启动后端，跑健康检查与登录验证。

## 6 校验

每次恢复必须做三件事：

1. 对象文件 SHA-256 与备份前一致。
2. 数据库关键表计数与备份时刻一致（`file`、`app_user`、`audit_log`）。
3. 抽样登录、列表、下载各一次。

## 7 注意事项

- 备份介质离线存放，不要长期插在服务器上。
- 每月至少一次恢复演练，记录写入 `_private/docs/qa/`（本地归档，不入库）。
- 迁移脚本必须随发布包保存，否则数据库无法重建结构。
- 恢复前先确认备份快照时间，避免用旧快照覆盖新数据。
- restic 仓库不可与生产目录同盘：单盘故障会同时丢失两份数据。

## 8 已知限制

| 限制                         | 影响                        | 缓解                               |
| ---------------------------- | --------------------------- | ---------------------------------- |
| 单机单盘                     | 全量备份与生产同盘时无隔离  | 外置介质 + 定期离线保存            |
| 全库恢复时间随数据量线性增长 | 大容量时超过 48 小时        | 分卷备份、优先按项目恢复           |
| restic 需从镜像获取          | 官网直连不稳定              | 通过可用镜像下载并校验 SHA256      |
| 无 UPS                       | 备份过程中断电可能损坏 dump | 备份任务放在低负载时段，完成后校验 |
